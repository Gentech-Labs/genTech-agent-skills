# Grant Application Template

## Overview
Grant applications differ from job applications — they're project-focused, not role-focused. The narrative centers on what you're building, not who you are.

## Grant Categories

### 1. Crypto-Native Grants (they WANT crypto)
- Solana Foundation, Ethereum Foundation, protocol-specific grants
- Lead with: blockchain impact, ecosystem growth, developer adoption
- Artifacts: live repos, hackathon wins, test coverage

### 2. Blockchain-Agnostic Grants (frame as AI/utility)
- OWASP, OpenAI, Google, foundation grants
- Lead with: problem solved, not chain used
- Frame as: "AI agent security tool" not "Solana smart contract"

## Application Structure

### Header
```markdown
---
title: [Grant Name] Application
project: [Project Name]
applicant: [Name]
date: YYYY-MM-DD
status: Draft
amount: $X-Y (grant range)
apply_url: https://...
---
```

### Sections (in order)
1. **Project Name** — Clear, memorable
2. **One-Liner** — What it does in one sentence
3. **Problem Statement** — What problem you solve (1 paragraph)
4. **Solution** — How you solve it (1 paragraph)
5. **Why This Chain** — Why this blockchain fits (if crypto grant)
6. **Artifacts** — Proof of work (repos, tests, live demos)
7. **Milestones** — Deliverables with timeline
8. **Funding Request** — Amount + use of funds
9. **Team** — Who you are + track record
10. **Links** — Portfolio, repos, demos

### Artifacts Table Format
```markdown
| Project | Chain | Tests | Status | Repo |
|---------|-------|-------|--------|------|
| Project A | Solana | 44/44 | Live | github.com/... |
| Project B | EVM | 22/22 | Live | github.com/... |
```

### Milestones Table Format
```markdown
| Milestone | Deliverable | Timeline |
|-----------|-------------|----------|
| M1 | Core feature v1.0 | Month 1 |
| M2 | Integration + testing | Month 2 |
| M3 | Documentation + SDK | Month 3 |
```

## Narrative Patterns

### For Crypto Grants
- "Open-source infrastructure for [ecosystem]"
- "Bringing [innovation] to [chain]"
- "Building the [missing piece] for [use case]"

### For AI/Utility Grants
- "AI-powered [solution] for [problem]"
- "Security tooling for [growing threat]"
- "Open-source [category] that [benefit]"

## Submission Checklist
- [ ] Fill out application form
- [ ] Attach all artifact links
- [ ] Verify all repos are public
- [ ] Check test counts are accurate
- [ ] Confirm milestone timeline is realistic
- [ ] Submit before deadline (or confirm rolling)

## Pitfalls
- **Don't lead with the chain, lead with the problem** — "AI agent security" beats "Solana smart contract"
- **Artifacts > narrative** — Working code speaks louder than promises
- **Milestones must be verifiable** — "v1.0 with 10 tests passing" not "build core feature"
- **Don't over-promise** — Conservative timelines build trust
- **Cross-reference hackathon wins** — They prove you ship, not just plan

# DAO / Security-Fund Governance Questionnaires

Distinct from narrative grant drafts. Some fund programs (e.g. **TheDAO Security Fund** on Gitcoin, which revived the 2016 DAO's 75,000+ ETH to fund Ethereum security) run an **application as a questionnaire**: multiple-choice governance questions plus short open-ended ones. This reference captures the question shapes and the answering pattern that worked.

## Question shapes you'll see (and how to answer)

1. **"Have you previously operated a funding round?"** → Answer honestly: NO. Do NOT fabricate a track record. Immediately reframe with real strengths: "I run a production x402 payment gateway + verifiable automated workflows, so the accounting/payout/transparency mechanics don't worry me; I'd lean on the fund's established rails and learn from curators."
2. **Decision-quality standard (multiple choice: AI-assisted / 200 verified voters / both)** → Pick the one you can genuinely guarantee. AI-assisted is the honest pick for a first-time operator — getting 200 *verified* voters is not something you control.
3. **"How do you ensure sufficient participation (~200+)?"** → Even if you chose AI-assisted (no hard gate), still show a real plan: lower friction to zero, target existing communities directly (badge holders/auditor networks), make participation visible/accountable, reward actual impact.
4. **"Who makes allocation decisions? (A open voters / B curated / C AI / D hybrid / E other)"** → **D Hybrid** is the honest default: open voters drive core QF signal, curated voters (e.g. ETHSecurity Badge holders) add a vetting layer, AI adds sybil-resistance + auditable payouts. Frame as checks-and-balances, not any single gatekeeper.
5. **"Ideal focus / eligibility?"** → Pick a **differentiating frontier**, not "audit everything." Strong thesis for Jordan: **AI-agent / autonomous-payment security** (agents now hold keys and sign txs with no human per-step) — wallet-authorization UX, phishing, prompt-injected txs, spending caps. Eligibility: independent researchers/auditors/tooling devs with a verifiable repo + real deliverable. Explicitly exclude marketing-disguised "security work" and paper-only proposals.
6. **"How will you advance the governance mechanism?"** → Two-part honest answer: (a) reuse the proven QF/ranked-choice rails, don't reinvent; (b) advance only where your real ops strength applies — verifiable payouts, sybil/gaming resistance, live public ledger. Don't overclaim a governance revolution.
7. **"How would you incorporate [key governance group / badge holders]?"** → Use them as a **vetting layer, not gatekeepers**. e.g. ETHSH Badge: public badge = accountable endorsement/eligibility veto; private badge = discreet safety valve to flag bad actors without burning a project publicly.
8. **"Ideal pool size (min / ideal / max)?"** → For a first round: **min ~$25K** (enough for 5-8 meaningful grants), **ideal ~$75-100K** (attracts serious applicants, ~10-15 projects), **max ~$250K** (a stretch ceiling within a large endowment's annual yield). Give reasoning, not just numbers.
9. **"What makes you a good choice despite no prior experience?"** → "The part people fumble is operations — accounting, verifiable payouts, honest reporting. That's my day job." Keep the transparency/auditability theme consistent; it is the credible differentiator.

## Honest-first-operator posture (the core lesson)

Jordan consistently steers toward **honesty over inflated claims**, especially for a security fund that rewards integrity:

- **Never claim experience you don't have.** A reviewer who catches a fabricated track record disqualifies you instantly.
- **Reframe "first time" as an advantage in the honest way:** "I'm not doing this to check a box — I live in the security-funding problem." Pair with the concrete strength (infrastructure ops, auditability).
- **Consistent theme beats scattered credentials.** Pick ONE credible through-line (transparency / verifiable accounting / "auditability is my day job") and let it carry every answer.
- **Lean on the fund's own rails + curators** for the mechanism you haven't run; improve only where your real strengths apply. This reads as humble + capable, not arrogant.

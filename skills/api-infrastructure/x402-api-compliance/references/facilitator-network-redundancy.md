## Redundancy rules (Jordan, Aug 19 2026)

1. Every network we advertise must have ≥1 wired facilitator + payTo. Never advertise a
   rail you can't settle (the "traffic but no revenue" leak).
2. Aim for 3-4 alternatives per network where the ecosystem allows; fail over on primary
   outage.
3. Base is the most resilient (4 facilitators), Solana second (4). Avalanche, Algorand,
   Sei, SKALE, Robinhood are single-facilitator today — the gaps to close as new
   facilitators come online.

## How to add a new settlement rail (the Solana pattern, proven Aug 19)

Adding a rail = 4 edits + restart, all driven by a payTo address. `enabled_networks()`
auto-drops any network without a payTo, so a rail is inert until you set its payTo — that
is the intended safe fail-safe (never advertise an unpayable rail).

1. **NETWORKS entry** in `server.py` — `network` (CAIP-2), `asset` (token address/mint),
   `decimals`, `payto_env`, `payto_default: ""`, `extra: {name, version}`. For Solana the
   asset is the SPL mint (e.g. USDC `EPjFWdd5...`), NOT a contract address.
2. **Routing** — extend the `elif is_avalanche or is_xlayer:` dispatch branch to include
   the new network's `is_<net>` flag, routing through the matching facilitator (PayAI for
   Solana). Check `_proof_network()` prefix detection works (e.g. `startswith("solana:")`).
3. **payTo env** — set `X402_PAYTO_<NET>` in the gateway `.env` + add the network name to
   `X402_NETWORKS="...,<net>"`.
4. **Restart + sync discovery files** — `systemctl restart x402-api`, then update BOTH the
   static `/var/www/gentechlabs/.well-known/x402-bazaar` AND `x402` (and copy `x402` →
   `x402.json` alias). Re-decode the live 402 `accepts[]` to confirm the new rail is
   advertised with its payTo.

**Verification:** decode the live `Payment-Required` header and confirm the new network +
payTo appear: `curl -sD- <endpoint> | grep -i payment-required | base64 -d`.

## Pitfall — manifest/discovery vs live 402 drift

The gateway's live 402 `accepts[]` is generated by `enabled_networks()` (correct, drops
unpayable rails). But the STATIC discovery files (`/var/www/gentechlabs/.well-known/x402`,
`x402-bazaar`, `x402.json`) are hand-maintained and drift — they can advertise rails the
gateway can't settle (e.g. listing 7 chains while only 4 are wired). Always diff the live
`accepts[]` against the static manifest files, and align the static files to only the
settleable set. Marketplace crawlers read the static files, so stale phantom chains there
"advertise" unpayable rails even when the live 402 is correct.

## Pitfall — disk-full blocks gateway file writes

A 100% full disk silently fails `patch`/`write_file` on gateway files ("No space left on
device") even though the process itself keeps running. Symptom: gateway healthy but edits
won't save. Free space BEFORE building: delete corrupt `.partial` backups (verify with a
zipfile/validity test first), purge npm/pip/apt/journal caches, and clear stale
pre-update state-snapshots. Check `df -h /` first when an edit fails for no clear reason.

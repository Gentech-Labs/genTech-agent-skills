# Pitfalls — part 3 of 3 (LIVE)

Part of the `develop-and-verify` ledger. **Index, part list and the census rule: `pitfalls.md`.**

- **A size comparison between a server table and disk is a free SYNC-HEALTH check, and its exceptions carry the meaning.** Of 3,363 files, 13 broke the uniform delta — and **every one was NEGATIVE and every one had an mtime within the last four minutes: `server − disk = +28` for a synced file, `+28 − (unsynced bytes)` for one edited since its last push.** **So an unexpected delta is not noise to discard: it is a file with unpushed local edits, identifiable to the minute.**
- **A projection in "months" must be a CALENDAR month; dividing a cap by a rate and then by 30 or by the measurement span gives different numbers with the same label.** A retention forecast of "8.0 and 12.1 months" was counts of the **35-day measurement period**, not months — the calendar values were **9.4 and 14.2**, because 35/30 ≠ 1. **The direction and ratio survived; the unit did not.** **State the rate, the span it was measured over, and the divisor explicitly, or a projection is not comparable to the plan it is being compared against.**
- **When a peer admits an error, verify the ADMISSION too — their correction is a claim like any other, and it can be narrower or wider than the truth.** A peer retracted two of their own findings; the retraction reproduced, **but the retraction's own supporting count was wrong in the same way as the original defect (a depth-2 glob missing depth-3 files)** — **the second-order error is the one that shows the pattern is a habit rather than a slip.**

- **"EXACTLY [N values]" is a UNIVERSE-SCOPED claim, and for an enumerable set the universe is the COMPARISON refs — publish the ref set in the SAME sentence as the word.** An exhaustive achievability table ("the achievable totals are exactly these fourteen") was computed over eleven head refs; the host also carried three tags, and widening the universe by those tags admitted **eight more values**. **The list was not wrong — the word claimed more than the universe it was computed in.** If a set is enumerated by varying a parameter, the parameter's range IS part of the claim.
- **A comparison ref is an OPERAND, not a FILTER — the only-here set is NOT monotone under swapping it.** Adding comparators shrinks an only-here set only when the comparators are the same objects; **a different `main` changes which objects count as shared.** Measured: the same forge side against `refs/heads/main` (a stale ref) gave **13,592 exclusive with 399 media**; against `refs/remotes/vault/main` (the real one) gave **11,063 exclusive with ZERO media** — and **all 399 media in the first subtraction were reachable from the second ref, i.e. exclusive to nothing.** **Before quoting an only-here count, name BOTH operands and check that the comparison ref is not stale.**
- **`git rev-list --objects` emits root trees with NO path, so "pathless objects" are not only commits — read the type breakdown before equating them.** A prune-exposure figure of "644 with paths, 236 pathless" was described as if pathless meant commits; **the 236 were 118 commits AND 118 root trees**, and the with-path 644 was 561 trees + 83 blobs (not "files"). **The composition is what turns "some media" into "83 blobs' worth of content plus 797 structural objects" — a count of objects is not a count of files until the types are stated.**
- **When a counted partition disagrees with a peer, suspect your RULER before their data — and state which base set the ruler ran over.** Our partition of 644 objects differed (155/367/122 vs 117/522/5) because I counted "second path segment" over a subtree while they counted it over the whole set; **under their stated ruler the counts matched to the digit (357/74/34/9).** **A partition count is only comparable if the base set it was computed over is named, not just the pattern.**

- **A stated inclusion/derivation direction is FALSIFIABLE against the counts in the same sentence — check it: a subset cannot be larger than its superset.** A peer derived "equal count means equal set" from *"A ⊆ B, therefore only-B ⊆ only-A"* — **backwards: the true relation was only-A ⊆ only-B (880 ⊆ 1,236), and the arrow they wrote would put a bigger set inside a smaller one.** **The conclusion survived (equal count plus either inclusion direction forces equal set), but the stated derivation — offered AS the evidence — was not the reason.** When a peer hands you a derivation, verify the arrow, not just the number.
- **A ruler needs its DENOMINATOR stated, not just its pattern — the pair to "state the pattern set a count came from".** Two scripts over one tree returned **522 and 367 for what reads like the same question**: one counted paths whose first two segments are `A/<x>` (every file beneath), the other required three segments. **Both numbers were true; `"paths under A/"` names neither.** **So: a count is only comparable if the pattern set is stated, AND a count over a subtree is only comparable if the BASE SET the ruler ran over is stated too.**
- **When your own citation (line/path/section) is wrong, fix the ARTIFACT, not the record — a path+line convention exists so the next reader can go there and find the thing.** A correction block sat at line 117 while the reply cited 115; **the fix is two characters in the durable file, not a note in the margin.** **A scoped claim can be CHECKED; a bare one has to be TRUSTED — and that applies to line numbers as much as to counts.**
- **An exposure figure should be quoted WITH ITS OPERAND attached when the operand changes the answer.** The same forge side against six refs vs twelve refs gave **880 vs 1,236 objects** — but the **blob sets were identical in both directions (b6−b12 = 0, b12−b6 = 0)**, so the operand moved 356 objects of directory-and-commit history and **not one file**. **Quote the quantity with the operand that a real action (a prune) would actually touch, and separate the answers that move from the answer that does not.**
- **A registry keyed on a VALUE is blind to that value's SURFACE FORMS — enumerate the forms a claim was ACTUALLY published in, or the tool cannot see the lane it was written about.** One claim appeared as `5 MiB` / `5 MB` / `5MB` / `5242880` across four notes; a registry listing only the first form reported it **CLEAN twice**, while the same limit was being hardened into a shipped tool elsewhere. **The key is not the value, it is the value's spelling — and a checker that normalises nothing normalises away the finding.** Found by pixel, 2026-09-28.
- **A DERIVATION OFFERED AS EVIDENCE MUST BE CHECKED AS EVIDENCE — state which claims you RAN and which you REASONED, or the reader cannot tell them apart.** One note reported a measured set difference — *"both directions are zero, verified"* — and one paragraph later an inclusion arrow it had **never executed**; the arrow was **backwards**, and falsifiable its own arithmetic before anyone else read it (a subset cannot be larger than its superset, so `1,236 ⊆ 880` was impossible while both counts stood). **The measured claim reproduced; the reasoned one was wrong; both were written at the same confidence and the page could not distinguish them — the same defect as citing an artifact by path without a digest.** **COROLLARY: a conclusion can rest on a CHECKED fact while its stated reason is broken, so a VERIFIED ANSWER IS NOT EVIDENCE THAT ITS DERIVATION WAS RUN.** When a number survives and the explanation was decoration, say which was which — otherwise the plausible mechanism is the thing that travels. Found by pixel, 2026-09-28.
- **A guard that NAMES what it is about to destroy and then destroys it is a log line wearing a guard's name — read the lines AFTER the warning, not just the warning.** An apply-path content guard built a list of seat-only files, printed them, and then ran `rmtree` + `copytree` with **no `continue`, no skip, no exit between them** — so it reported the loss it was causing and caused it. **The question is not "does the check run before the destroy", it is "is there a BRANCH between them that can decline."** **And the fix carries a trap of equal weight: the at-risk list held TWO claims — `exists only in the seat` (real, unrecoverable) and `differs from core` (the NORMAL case after any core edit) — so a hard block on the whole list refuses legitimate updates and gets the guard disabled, which is worse than no guard. Tier the claims: BLOCK the strong one, WARN the weak one.** **Corollary, and it was a second lie in the same tool: a summary that reports a REFUSED write as `:updated` is the same defect one layer up.** Found by labs, implemented by gentech, 2026-09-28.
- **Two agents converging on ONE canonical artifact must NAME the survivor out loud — "the better one survives" is a tiebreak each agent can run privately and reach the OPPOSITE answer on, in the same minute.** Both of us independently judged the other's test stronger and deleted our own, so for a few minutes the guard had **no test at all**. Unlike a duplicate file, this failure leaves a HOLE rather than clutter, and nothing reports it: each deletion looks like tidying from the side that made it. **Coordination needs an explicit "X is canonical" in the record, not a convergence rule.** **Corollary for the control itself: a "pre-fix" control anchored on `HEAD` stops being a control the moment the fix is committed — the commit removes the only evidence the control could have run — so pin the pre-fix revision to an explicit SHA.** Found by gentech + labs, 2026-09-28.
- **A directory/aggregate DIGEST is INSTRUMENT-SPECIFIC — publish the EQUALITY claim, and name the instrument, not just the hex.** Two independent implementations walked the same two trees and produced `0072311aca63` and `3a59b16fac6f` for the SAME property, and both were right: a digest is a function of walk order, path encoding, separator, and which files are excluded. **"The two directories are identical" is the claim; the hex is a property of the instrument that computed it.** Two instruments agreeing on the EQUALITY is strictly stronger evidence than one instrument's hex being reproduced — and reporting the hex as if it were the fact is the same error as quoting a size without its denominator. **COROLLARY — a value is a claim about a MOMENT: publish a moving figure with the TIME it was read, or as a range with both ends named.** A ledger grew 69,923 -> 72,536 -> 72,925 chars across two notes in twenty minutes, so the same file was correctly described by three different numbers, and a reader quoting any of them without its clock gets a number that was true once. **And the mistyped pointer is the same family: a figure quoted back at the wrong note is a correct value with the wrong address.** Found by pixel (instrument) and gentech (the three vintages), 2026-09-28.
- **A META-DISCUSSION of a retracted claim satisfies both the form and the cue — a retraction sweep cannot tell a note that ASSERTS a figure from one that QUOTES it in order to withdraw it.** A sweep keyed on the withdrawn form plus the absence of a correction marker flags the very notes doing the correcting, so the finding lands in the retraction's own write-up. **The fix is the marker list one level down: the check must ask whether the note USES the figure or MENTIONS it, and a marker's presence is itself a claim.** **COROLLARY — "clean" is a claim like any other and needs its INSTRUMENT and its LANE named: "the sweep is clean" without which sweep and which scope is the same defect as a count without its denominator.** Two instruments in this fleet are both called "the sweep" (a stale-reply sweep and a retraction sweep), so the word alone is not a scope. Found by pixel, confirmed and extent-corrected by gentech (whose own 00-HQ audit record was among the findings), 2026-09-28.
- **A NUMBER IS NEVER SELF-LOCATING — this is the one sentence that unifies the whole family, and it is pixel's.** Each member is a claim whose **printed form carried no sign of what it was relative to**: a **RULER** (522 vs 367 — the denominator never named), a **UNIT** (`5 MiB` vs `5 MB` — a substring wearing a number's clothes), an **ARROW** (`only-12 ⊆ only-6` — a derivation offered as evidence and never run), a **VINTAGE** (core vs seat — two ages of one file), an **ADDRESS** (note A vs note B — the right value in the wrong document), and a **PATTERN SET** (a failed grep — searching lowercase against an uppercase entry returns zero, and zero reads exactly like never adopted). **A LIST OF SIMILAR MISTAKES IS NOT A FAMILY; what makes these one is that none of the six could be checked without first asking what it was measured against.** **SELF-CATCH, and this is the demonstration rather than the fix: this entry read "none of the five" and stopped its enumeration at five while the family had ALREADY REACHED SIX — so the sentence that unifies the family was ONE MEMBER BEHIND ITS OWN MEMBERSHIP, and it was correct in both places. The original wording is kept second only to the count: the entry that says "none of the N" is ITSELF a claim whose printed form carries no sign of WHEN it was true.** **COROLLARY — A DELTA CARRIES ITS ADDRESS WITH IT: publishing a delta against a baseline taken from a DIFFERENT document produces a number that could only be right if the mis-attribution were right, so a wrong address compounds into a wrong quantity.** Name the baseline; never infer it. **COROLLARY — a table whose column mixes UNITS reads as smooth growth when the middle row is measuring something else; put a moving series in one unit or the column cannot be read down.** **PROCESS: before quoting a peer's number, re-read the note it came from IN THE SAME ACTION — the failure mode is not ignorance of the value, it is CONFIDENCE IN THE VALUE'S ADDRESS.** Found by pixel (the address, and the family's unifying sentence) and gentech (the fifth appearance, and both notes corrected in place), 2026-09-28.
- **An instrument built to catch a defect class can carry that class in its OWN matcher — and a two-line asymmetry inside one file is invisible because each line is locally correct.** A retraction sweep flagged 17 code locations; **nine were one missing digit boundary**: `_norm_expr` collapses whitespace, so `25 * 1024 * 1024` normalises to `25*1024*1024`, which CONTAINS `5*1024*1024`, and the expression matcher was a raw substring while the figure matcher three hundred lines up had the guard. **When two matchers in one file guard the same way, make BOTH guard — the unguarded one was the one built for the cases that matter.** **Measured fix, tested both directions: the boundary clears 9 of 17 and keeps all four genuine uses.** **COROLLARY — an artifact must carry its ROOT: a tool that emits `files_scanned` but not the directory it scanned publishes a DENOMINATOR WHOSE NUMERATOR NEVER APPEARS, and an unstated default that is a fraction of the documented scope makes a clean read and an unread tree the same sentence.** **COROLLARY — a PLAUSIBLE EXPLANATION is not a census: naming one true cause and letting it stand for the whole list is the 503-shaped move at report scale, and it is undetectable precisely because the cause is true (it owned 4 of 17).** Found by pixel (the decomposition, the boundary, the fix) and gentech (reproduced the 9/4/4 at the artifact, tested the fix, pinned the missing root), 2026-09-28.
- **A FAILED GREP IS NOT EVIDENCE OF ABSENCE; IT IS EVIDENCE OF A FAILED GREP — a grep result is a claim about a PATTERN SET, not about a file.** Searching lowercase `never self-locating` against a ledger entry written in caps returns zero, and zero reads exactly like "it was never adopted": **the cheapest false absence in the fleet.** **Corollary of the same shape as the case-sensitive marker list: a search is only as good as the pattern it was given, and the pattern is stated by whoever ran it, so an absence claim must carry the pattern that produced it.** **COROLLARY — publish PER-FILE digests alongside any directory digest: `core/SKILL.md == seat/SKILL.md` by md5 is an equality claim any instrument can check, while a directory hex is a property of one walk.** Found by pixel (the near-miss), confirmed by gentech (the count: 1 uppercase hit, 1 case-insensitive, 0 lowercase), 2026-09-28.
- **Even a PER-FILE digest is a claim about a MOMENT — the durable form is the EQUALITY, not the hex.** Per-file md5s read `81e39c84c7d5` / `11e5e9591370` at one point in the evening and `6fcf8248573687ed9154467236321387` / `237c41a154563234054788f5ea89045f` a few lessons later, **and both readings were correct**: the files GREW between them. **So the form that travels is the EQUALITY PLUS THE CLOCK — `core == seat` AT A NAMED TIME, with per-file digests as the checkable detail — never a bare hex, which is what the whole vintage family has been about all night. A hex SNAPSHOTS; it does not TRAVEL. FOUR readings of one file in one evening were ALL correct — `81e39c84c7d5`/`11e5e9591370`, then `a63d03ec…`/`d9367dbf…`, then `773c84717717`/`f45cb37873a6`, then `c2fd4b4f9359391e9419d493ec431579`/`01c52aaa794aab5d1bf56511a1aa8fbd` at 21:39:57Z — and the same is true of a COUNT, which is the same claim with a different subject: the ledger read 127 → 128 → 130 → 131 → 134 → 137 in one evening, so a count published without its moment is one edit behind by the time it is read and the reader has no way to know. Publish the moment, or a floor. **AND THE REMEDY IS NOW MEASURED RATHER THAN AGREED: across this exchange two seats read the same file FOUR times and agreed ZERO times, every reading individually correct; the FIRST reading the two seats agreed on TO THE CHARACTER (`558320a426671124f56cfa6750315bf3` / `b78654d67dc71a553040641f8230485b`, 86,275 chars / 138 items) was the first one PUBLISHED WITH ITS MOMENT (21:45:30Z) — and the reason it converged is not that the file stopped moving, it is that the moment was named and nothing moved between the two reads. Name the moment and two readers converge; publish the value alone and they cannot, because the answer to WHEN is doing all the work.** Raised by pixel (the clock) after gentech's equality turn.** Confirmed by gentech across all four seats, 2026-09-28.
- **A SUPPRESSION RULE IS A GUARD IN REVERSE AND NEEDS BOTH CONTROLS — the case that must FIRE (a bare stale claim with no marker) and the case that must STAY SILENT (a genuine correction).** A code-surface hint list suppressed any hit with an ordinary word within ±4 lines: `# raise an error if the path is missing`, `# strip a substring of the name`, `# conservative estimate of the queue depth` each turned a bare stale constant SILENT with **no correction present at all** — the exact mirror of the false positives a digit boundary had just removed, same tool, same evening, opposite sign. **A file that mentions an error or a substring is the file whose comment happens to be chatty, which is a property of the author's PROSE, not of the constant.** **COROLLARY — A MARKER IS A CLAIM; A HINT IS A NEIGHBOUR: require that someone SAID something (a stated correction) rather than that a word was NEAR, or the guard's strength varies with how talkative the surrounding code is.** **AND THIS IS WORSE THAN THE MIRROR IT LOOKS LIKE, because a hint-keyed suppression is A SELECTION RULE POINTING THE WRONG WAY: its permissiveness RISES WITH THE AMOUNT OF PROSE IT IS READING.** Explanation concentrates around the constants that mattered enough to explain, so the guard is **STRONGEST ON TERSE CODE AND WEAKEST ON COMMENTED CODE — it audits least the files someone thought hardest about, and passes exactly the artifacts whose authors ALREADY KNEW the value was contentious**, which is the population most likely to be carrying a stale constant under a comment saying it is fine. **A MARKER IS A CLAIM; A HINT IS A NEIGHBOUR — require that someone SAID something rather than that a word was NEAR, or the guard's strength is a property of the author's verbosity.** **COROLLARY — a harness must be validated by the case it is REQUIRED to catch: a silent CONTROL means the harness is broken, not that the tool is clean (scope rules like `code_only_files_matching = 'scripts/'` make a probe that never runs look like a clean result).** Found by pixel (the false-negative measurement, the window bound, the broken-harness catch), reproduced with a firing control by gentech, 2026-09-28.
- **A TRUE CAUSE IS THE MOST DANGEROUS INCOMPLETE EXPLANATION, BECAUSE CHECKING IT CONFIRMS IT.** The dangerous incomplete explanation is not the FALSE one — a false cause dies under checking — it is the TRUE cause **stated at REPORT SCALE**: checking confirms it, and confirming it is what promotes it to stand for the whole list. A census said 17 code findings were "over-broad by design"; the by-design case was real and owned **4 of the 17**, so a true cause, confirmed by checking, silently covered the other 13. **This member sits BESIDE the family rather than inside it: the others are claims about what a NUMBER is relative to, this one is about what a CAUSE is relative to.** Found by pixel (the rule) and gentech (the instance), 2026-09-28.
- **A CARVE-OUT THAT SUPPRESSES SELF-REFERENCE IS PERMANENT INFRASTRUCTURE, NOT A CLEANUP — every patch written in this family QUOTES the form, so each fix creates a new instance of the class it fixes.** A boundary guard clears a **MISREAD** (`25 * 1024 * 1024` read as `5 * 1024 * 1024`) — one-time, and it cannot regress. A comment/docstring carve-out clears a **SELF-REFERENCE**, and it must run forever: **the better a tool gets at DESCRIBING a defect, the more of its own text contains the form.** Measured: adding a patch comment that explains the boundary immediately made the fixed file a finding again at new offsets. **So a two-part fix is not a partition — one half is a cleanup and the other is load-bearing infrastructure, and treating them as "9 + 4" gets the durability wrong.** **Corollary: a heuristic for the marking syntax (a backtick rule) fails exactly on the patches that knew the most, which is why AST-level blanking is the right shape.** Found by gentech (the durability), confirmed by pixel, 2026-09-28.
- **A NOTE'S NUMBER IS ALWAYS AN ADDRESS, NEVER A VALUE — a note is written from the state at the moment of writing, and the artifact keeps moving underneath it.** A ledger grew 127 → 128 → 130 → 131 → 134 across one evening of notes, so **every count published in a note is one edit behind by the time it is read, and the reader has no way to know.** **It matters MOST for the seat other seats derive from: a reader who takes the number forward inherits the gap silently.** Publish a moving figure with the time it was read, or as a floor. Found by pixel, confirmed by gentech, 2026-09-28.
- **A FIX THAT CORRECTS A VALUE RE-STALES; A FIX THAT REMOVES THE VALUE FROM THE CLAIM CANNOT — prefer "none of the N" to "six".** The family's unifying ledger entry enumerated five members when the family had reached six. The offered fix was **widen the clause to six** — which replaces a wrong count with a right count and re-stales at seven: **a one-instance fix wearing a class fix's clothes.** Written as **"none of the N"**, the sentence no longer NAMES a number and therefore cannot be behind one. **The same distinction as a boundary guard versus a carve-out, applied to prose: fixing the VALUE versus stopping the value being CARRIED.** **THREE-FOR-THREE IN ONE EXCHANGE: a root cause can be right while its stated FIX is one level too shallow — the same was true of the per-file-digest suggestion (a hex is better than a directory hex and still snapshots).** **AND THE FAMILY CAUGHT ITS OWN RESOLUTION: the vintage question was settled by "two independently computed md5s agree on the same value", and THAT SENTENCE WAS ITSELF A MEMBER — the digests agreed at ONE vintage, and the publication quoted a value computed before the author's own commit, so the claim of agreement had already expired when it was read, with two intervening commits between the two reads. - **THE CONFIRMATION THAT A DIAGNOSIS WAS RIGHT IS WHAT STOPS THE SEARCH ONE STEP EARLY — a correct root cause makes the FIRST AVAILABLE FIX look like the whole answer.** A true diagnosis is confirmed by the first fix that addresses it, and **confirmation is what ends the search**, so the fix that works is where the inquiry halts — one level short of the class. **It therefore tells the next reader where to look: NOT AT THE FIX THAT FAILED, but AT THE FIX THAT SUCCEEDED, because a working fix is the only kind that can be ONE STEP SHORT without anyone noticing.** **FALSIFIABLE PREDICTION — the more work a diagnosis took, the SHALLOWER its first fix will be, because a hard-won diagnosis FEELS complete and the feeling is what ends the search; test it by naming the diagnosis, the first fix, and whether the fix closed the class or only the instance.** **Tested against three instances in one exchange (pixel): (1) the 9/4/4 — diagnosis "one missing digit boundary" exactly right, first fix "add the boundary" missed the hint silences; (2) the per-file digest — diagnosis "a directory hex is instrument-specific" right, first fix "per-file md5" one turn short because a hex snapshots and does not travel; (3) the family entry — diagnosis "the family is one member behind its own description" right, first fix "widen the clause to six" RE-STALES at seven. IN ALL THREE THE DIAGNOSIS WAS CONFIRMED AND THE FIX WAS THE FIRST AVAILABLE ONE.** **Corollary of the same shape as the true-cause rule, one level up: the true cause explained the SYMPTOM, and the first fix explained only the symptom the cause was found through.** Found by gentech (the mechanism), tested against all instances by pixel, 2026-09-28.
- **THE DRIFT IS NOT ALWAYS AT THE OBSERVATION — IT CAN BE AT THE RECITAL: a number can be MEASURED correctly, WRITTEN correctly, and then carried into a sentence without being RE-DERIVED for it.** The record read `139 items` and the message composed that same minute said `134`; the count had been read and written correctly at the earlier moment it belonged to, and then TRAVELLED WITH THE MESSAGE rather than being computed FOR it. **This is the sixth member's THIRD appearance, and its third variant — the same family, one step further along: not a stale measurement, a stale RECITAL, and no amount of care at the instrument would have caught it, because the instrument was not the thing that was wrong.** **THE REMEDY IS THEREFORE IN THE FORM OF THE CLAIM AND NOT IN MORE CARE AT THE INSTRUMENT: a form that CARRIES ITS OWN MOMENT cannot be mis-transcribed into a claim about a different one.** Name the moment IN THE SENTENCE, not beside it. Found by pixel (the instance and the diagnosis), confirmed by gentech against its own record, 2026-09-28.
- **A COUNT AND A SIZE ARE BOTH BLIND TO CHANGE — ONLY A DIGEST DETECTS IT.** Across one evening `SKILL.md` held at **35,099 characters while its md5 moved through `f45cb37873a6` → `504189db4166` → `b78654d67dc7` → `9090023eb165` → `b14219ad3141`** — FIVE IDENTICAL COUNTS, FIVE DIFFERENT FILES, and content changed between every one of them. **So of the three things a reader might quote about an artifact, THE TWO THAT LOOK LIKE A DESCRIPTION ARE THE TWO THAT CANNOT TELL YOU ANYTHING CHANGED: a count and a size are blind across the whole window, and only the digest caught it.** **Publish the digest WITH its clock; treat a count as a FLOOR and a size as a property of the wrapper, not of the content.** **COROLLARY — the ledger's own item count is the same kind of column (127 → 128 → 130 → 131 → 134 → 137 → 139 → 140 in one evening), and worse: because an item can be EDITED IN PLACE, a lesson can change while the count does not move AT ALL — a genuine blind column, not merely a lagging one.** Found by pixel (the measurement), verified by gentech against its own record, 2026-09-28.
- **A FAILED COMMAND IS NOT A FAILED TASK, ANY MORE THAN A SUCCEEDED COMMAND IS A FINISHED TASK — VERIFY THE ARTIFACT IN BOTH DIRECTIONS.** A peer's commit command was rejected by the shared tree FIVE TIMES, and the files were nonetheless committed, because a concurrent sweep-commit picked them up: reporting "the commit failed" would have been a FALSE failure, and reporting "the commit succeeded" off the later exit code would have been an unchecked success. **A NONZERO EXIT IS EVIDENCE ABOUT THE COMMAND; A CLEAN TREE IS EVIDENCE ABOUT THE TREE — and only one of those is the task.** **The instrument is the same one in both directions: read the ARTIFACT (HEAD copies byte-identical to disk, working tree clean for the paths in question), never the exit code — and in a MULTI-WRITER tree, a command that fails can still have had its effect delivered by another writer, so the failure report is as unreliable as the success report.** Found by pixel (the instance, five rejections and a rescue), 2026-09-28.
- **FOR A THRESHOLD DECISION A STALE MEASUREMENT DOES NOT MERELY MISINFORM — IT DELAYS THE ACTION BY ITS OWN DRIFT.** Everywhere else in this family a stale figure costs a reader a CORRECTION; at a GATE it costs a DEADLINE, because the threshold is what decides WHEN to act, so an optimistic reading makes the gate fire LATE BY EXACTLY THE AMOUNT THE ARTIFACT MOVED. **So a gate must READ THE ARTIFACT AT DECISION TIME rather than carry the number in the entry — the clock remedy applied where the cost is a missed moment rather than a wrong sentence.** **COROLLARY — state a threshold in the unit that actually BOUNDS it: for a size cap the honest unit is ITEMS (at the average item size), not characters, because a rate measured across a burst is a PEAK-RATE ARTEFACT and cannot be forecast from; measure the rate PER INTERVAL rather than averaging it, since a burst-driven artifact decelerates and a mean rate overstates the future.** **COROLLARY — provenance is the one thing an extraction can break while looking perfect, so make the rule CHECKABLE: count the items naming a seat BEFORE and AFTER, and if the number moves, something was REWRITTEN rather than MOVED.** Found by pixel (the threshold rule, the unit, the provenance check), 2026-09-28.
